## surface-territory card rewritten with corrected failure mode

The 2026-08-12 roadmap card framed the bug as an explicit `--quality` "returning 'No qualities selected' instead of running it." The command never errors and never prints that string — it is the prompt-builder line written into the review's `_prompt.md` when `canon.Narrow` leaves zero qualities (internal/prompt/prompt.go). Both the rubric and ad-hoc paths then run the reviewer against an empty set and print an ordinary `verdict: clean`; `Narrow` discards the dropped set, and neither `result.json` nor the collect response carries selected/excluded qualities. The card is rewritten on the corrected frame and now names both reporting surfaces (CLI line; `result.json`/collect refs) plus the `--quality` territory bypass. The added result-payload shape is my recommendation in the card, not yet Michael's call.

Title changed to `report territory-excluded qualities` — the old title read as the qualities that *survived* territory filtering (the reviewed set), the opposite of the ask. The filename move is deliberately not mine to make: `order.yaml` tracks the slug and is operator-owned, so the board's `rename to slug` gesture on the mismatch-flagged card (ranger serve) commits the file move and sidecar update together. The card sits in a designed title≠filename mismatch state until that click.
